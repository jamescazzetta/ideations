# Find the assumptions that matter

Choose the 3–5 claims the idea most depends on; use fewer when enough.

Follow the [shared rules](../../docs/CONTRACT.md). Read CONTEXT.md and any OFFER, MARKET, CHALLENGE, EVIDENCE and previous ASSUMPTIONS notes.

## Work through the idea

1. Ask what would have to be true for this idea to be worth the user's time. Prioritize real pain and reachable users; put technical feasibility first only when it is the main uncertainty.
2. For commercial ideas, consider buying authority, willingness to pay, a reachable acquisition route, and delivery/support costs. Select the decisive unknowns rather than listing every risk.
3. Phrase each assumption as a specific claim that evidence could contradict. Identify the cheapest credible test and what result would refute it.
4. Rank by consequence and uncertainty. Choose one assumption to test first and explain why it outranks the others.

## Save the map

Append to **ASSUMPTIONS.md** using `append-report assumption-map`. For each stable ID (A1, A2, …), record:

- The claim and why the idea depends on it.
- Evidence for and against it, with sources and dates.
- Uncertainty: LOW, MEDIUM or HIGH; consequence if false.
- Importance: DECISIVE or MATERIAL.
- Cheapest test and the observation that would refute it.

Mark missing inputs and provisional conclusions. Combine overlapping claims while retaining superseded IDs and failed assumptions in history. Use qualitative judgments, not a numerical scoring system.

Finish with the single assumption to test next. Suggest validation-designer if useful; leave the experiment design to that requested procedure.
