# Bridge to external evidence

Read [the shared contract](../../docs/CONTRACT.md). Trigger when the user asks for a concrete next action on an existing idea.

## Inputs and ownership

Read CONTEXT.md, canonical STATE.md, GATE.md, available OFFER.md, ASSUMPTIONS.md, VALIDATION.md, EVIDENCE.md and existing NEXT.md. Own only NEXT.md, appending a dated assessment and preserving notes. Missing state means SEED. Missing optional research is a limitation, not permission to launch it.

Check the applicable boundary before recommending action:

| State | Appropriate next action |
|---|---|
| SEED / RESEARCHED | Explain the missing assumption, experiment or gate; do not generate an execution or build plan. |
| VALIDATING | One action within the reviewed experiment, such as recruiting a relevant participant or offering the defined manual pilot. Require a reviewable assumption, predeclared thresholds and validation decision. |
| PROMOTED | A bounded customer-learning or onboarding-preparation action grounded in reviewed promotion evidence. New implementation still requires BUILDING. |
| BUILDING | Delivery, acceptance testing or release within the human's recorded scope and stop condition. |
| SHIPPED | Feedback, outcome measurement, repeat use/purchase, renewal, referral or support assessment within the existing release and customer commitments. Require reviewable release evidence. |
| PARKED / REJECTED / MERGED | Explain the disposition; no execution plan or automatic reactivation. |

If the state history, relevant evidence or decision cannot be reviewed, mark BLOCKED and identify the smallest missing input. SHIPPED remains terminal. A new product scope needs a separately authorized commitment under the lifecycle; a retention action cannot disguise a new build. Account for shipped customer work in portfolio opportunity cost.

## Output

Return at most 1–3 actions, normally one. Each names:

- The signal sought and relevant customer stage: acquisition, sales, onboarding, delivery or retention.
- Target person/channel, concrete deliverable and smallest effort/timebox.
- Completion evidence, useful denominator or baseline, and current prediction if recorded.
- Review date or sample limit, cost cap where relevant, and a continue/change/stop rule tied to the experiment or delivery scope.
- Whether it is proposed, already authorized, or observed complete. Never infer completion from a plan.

Prefer the action that addresses the present bottleneck: a discovery conversation about actual behavior, a scoped payment request, manual fulfillment, removing an onboarding obstacle, checking an accepted outcome, or learning why customers leave. Compare against doing less. A sustainable cadence is useful only while the evidence supports continuing; never extend a failed test by silently changing thresholds.

## Stop after planning

No roadmap, implementation, contact, publishing, spending, state mutation or automatic handoff. NEXT.md never authorizes execution. Performing an action needs applicable human authorization; preserve authorization already given without asking again. Actual observations belong in EVIDENCE.md through its documented owner, not invented records in this plan.
