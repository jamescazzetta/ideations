# Choose the next useful action

Propose the smallest action that would address the current customer or delivery bottleneck.

Follow the [shared rules](../../docs/CONTRACT.md) and [lifecycle](../../docs/lifecycle.md). Read CONTEXT.md, STATE.md, GATE.md and available OFFER, ASSUMPTIONS, VALIDATION, EVIDENCE and NEXT notes.

## Check what the state permits

| State | Appropriate next action |
|---|---|
| SEED / RESEARCHED | Explain the missing assumption, experiment or gate; leave execution planning for later. |
| VALIDATING | One action within the reviewed experiment, such as recruiting a participant or offering the defined manual pilot. Require the assumption, thresholds and validation decision. |
| PROMOTED | Customer learning or onboarding preparation grounded in reviewed promotion evidence. Implementation still requires BUILDING. |
| BUILDING | Delivery, acceptance testing or release within the user's recorded scope and stop condition. |
| SHIPPED | Feedback, outcome measurement, repeat use/purchase, renewal, referral or support assessment for the existing release and commitments. Require reviewable release evidence. |
| PARKED / REJECTED / MERGED | Explain the disposition; no execution plan or automatic reactivation. |

If the relevant state history, evidence or decision cannot be reviewed, mark BLOCKED and name the smallest missing input. SHIPPED stays terminal: a retention action cannot authorize new product scope. Include ongoing customer work in portfolio opportunity cost.

## Save the next action

Choose 1–3 actions, normally one, and append to **NEXT.md** using `append-report execution-bridge`. Each names:

- Signal sought and customer stage: acquisition, sales, onboarding, delivery or retention.
- Target person/channel, concrete deliverable and smallest time/effort budget.
- Completion evidence, relevant baseline or total count, and any recorded prediction.
- Review date/sample limit, cost cap where relevant, and a continue/change/stop rule tied to the existing test or scope.
- Status: proposed, already authorized, or observed complete.

Compare against doing less. Prefer resolving the present uncertainty over adding architecture or features. A sustainable cadence must respect the original failure thresholds.

Finish with the plan; this skill does not perform the action. Actual observations belong in EVIDENCE.md through its documented owner. A plan alone is neither execution authorization nor evidence of completion.
